τ-mux · AAA Feature Upgrade Programme

From baseline to AAA — every change, by phase

A 10-phase plan-of-plans that lifted τ-mux from a mostly-A codebase with named gaps into a release-shape product. Six sessions of Phase 7 polish carried the final 20 lifts on top of seven earlier landed phases. This document catalogues every functional change.

PHASE 0Foundation & verification

Set up the measurement and gating infrastructure every later phase would lean on. No feature changes — pure verification + tooling.

Landed

  • Per-feature grades pipeline — doc/feature_grades.json + scripts/build-feature-grades.ts render the canonical scorecard via bun run report:feature-grades.
  • Coverage baseline — scripts/check-coverage.ts snapshots coverage and the gate fails any later phase that regresses it.
  • Phase 0 audit matrix (phase0_audit_matrix.md) — categorical pass/fail across every feature.
  • S1 invariants pinned — atomic-write + logger + telegram-db file mode 0o600 tests.
  • S3/S7 telegram outbound regression tests — chatId allow-list + outbound cap invariants.
  • S4 token entropy floor warn-on-0.0.0.0 regression test.

Why it mattered

Without P0 the rest of the programme is unaccountable: features could silently regress under each phase's commits. Coverage and grade reports become the canonical artefacts every later session updates.

PHASE 4Security hardening (LAN-visible mirror)

The web mirror serves arbitrary fd 3/4/5 sideband content to LAN-visible clients. Two structural fixes plus a Telegram payload surface tightening.

Landed

  • bf20f57 S2 / H.7 iframe sandbox — sideband HTML/SVG in the web mirror now renders inside an iframe sandbox="" with a strict CSP. Documented in doc/system-security.md.
  • c3ab2ff S11 / H.11 Telegram parse_mode allow-list — sanitizeParseMode at the transport boundary; only MarkdownV2 survives. HTML, Markdown v1, typos, attacker payloads all fall back to plain text.

PHASE 7Per-feature polish sweep — 6 sessions, 20 lifts

The biggest single phase: a polish sweep walking the per-feature grades and closing the named gaps in each. Split across six sessions because the long tail spans clusters B / C / D / E / F / G / H.

Session 1 — Cluster A foundation

cookie-store→B → A5f0c2f2

URL-host normalize on insert (Example.com, .example.com, EXAMPLE.COM collide as the browser does) + MAX_PER_DOMAIN = 500 evicts oldest entries inside one bucket so a hostile site can't dominate the global cap.

browser-history→B → Ab5a3b70

Extended normalizeUrl — lowercase host, strip fragment, strip default port — so visits to http://Example.com:80/?#x and http://example.com/ collapse into one history row.

manifest-scanner→A → S21530db

Realpath-aware $HOME boundary check — when the env value differs from its realpath (macOS firmlinks, Linux build-mount realpaths), the walk resolves the current dir and compares against the realpath'd $HOME so symlinked homes don't escape.

plan-panel→A → Sa67a0c5

PLAN_STATE_VALUES allow-list shared between plan.set and plan.update: a typo like state: "complete" now throws with a clear error (was silently coerced to waiting).

Session 2 — Search, metadata, health, theme infra

terminal-search→A → S56269da

Case + regex toggles (Aa / .*) with aria-pressed + localStorage persistence under hyperterm-canvas.search.toggles. findNext / findPrevious pass ISearchOptions { caseSensitive, regex } so xterm's SearchAddon honours the modifiers.

surface-metadata→A → Sb112dbe

30 s gitStaleCooldownMs guard — when a git status subprocess hangs past 0.8 × the 5 s timeout, the cwd is parked in a stale-set for the cooldown so subsequent ticks short-circuit instead of stacking parallel hangs (relevant on NFS / sshfs mounts).

health-checks→A → S9eb30a0

Remediation fix() channel mirroring the audits pattern: wire-safe fixLabel projection + runFix(id) + idempotency under same label. Sidebar pill can now render a one-click recovery button.

tau-primitives (chromeTheme infra)→S → Sd5cfa8e

Wired chromeTheme: system | graphite-dark | graphite-light | high-contrast end-to-end — bun-side pickWebSettings projects it on the wire; native + mirror both write data-theme=… so the token blocks activate regardless of OS preference.

Session 3 — User-visible UI

theme selector UI→S → S741560c

Four-way segmented selector at the top of Settings → Theme that emits chromeTheme through the existing updateSettings pipeline (closes the chromeTheme infra from S2).

pane-chip-rendering (ARIA)→A → Sac985b2

Chip host gets role="status" + aria-live="polite"; every chip carries an aria-label with the full value — cwd (full path), command (full command, no truncation), port (“Open port N (proto address, pid X)”), git (“branch X, N ahead, N behind, +X lines, −Y lines”).

notifications→B → Ad5b4829

Copy button on sidebar notification items (navigator.clipboard.writeText + .copied pulse, silent fallback). Disk persistence in $HT_CONFIG_DIR/notifications.json via new notification-persistence.ts with 300 ms-debounced atomic writes.

Session 4 — Cluster D + E

browser-pane (nav validation)→A → Sc17de81

isSplitDirection / isNavigableUrl / requireSurfaceId validators: browser.navigate rejects a missing url or typoed scheme; browser.open_split rejects unknown directions (no silent default); back/forward/reload require a non-empty surface_id.

audits (auto-rerun)→A → S237c10f

New runAndPublishAudits() helper called both at boot and after rebuildAudits() lands inside updateSettings. Stale audit:* rows are pruned on each pass; the legacy “audits disabled” row is cleared when audits repopulate.

event-writer (metrics)→B → A8763a36

EventWriterMetrics { sent, inFlight, failed, peakInFlight } via getMetrics(); Bun.write Promise decorated with .finally(…) so inFlight tracks true OS completion. A wedged consumer or runaway producer is no longer silent.

Session 5 — Cluster D + S4 follow-up

event-writer (bounded queue)→A → S727edf4

DEFAULT_MAX_IN_FLIGHT = 1024 with a dropped counter. When inFlight hits the cap, further send() calls return false + bump dropped instead of stacking pending writes — caps worst-case queued memory to ~1 MB.

editor-pane (save-race)→A → Sf6e5ae3

Structured conflictDetail { expectedMtimeMs, actualMtimeMs, actualSize } on EditorSaveResult for actionable UI dialogs; new force: true flag for explicit overwrites; out-of-band-delete detection (file vanished with non-null expectedMtimeMs surfaces a conflict instead of silently re-creating).

pane-chip-rendering (OSC 9;4 chip)→S → S7c5ea3b

Per-pane OSC 9;4 progress chip — ▰▰▱▱▱ 40% for normal, ⏸ ▰▰▰▱▱ 60% for paused, × error, … for indeterminate — wired through SurfaceMetadata.progress so the chip survives 1 Hz poller refreshes.

Session 6 — Cluster C + G

telegram-bridge (TTL prune)→S → S082f189

Age-based pruneOldMessages(cutoffMs) on the main messages table runs at boot with a 90-day cutoff alongside the existing link prunes. Closes the last named gap — a year of low-volume notifications across many chats no longer accumulates hundreds of MB of SQLite.

auto-continue (persistence)→A → S1f34791

Paused-surfaces set persists across restarts via $HT_CONFIG_DIR/auto-continue-paused.json (versioned v1, debounced atomic writes). Engine adds onPausedChange dep + hydratePaused boot hook. Closes the “user pauses agent → restart silently re-enables it” footgun.

browser-pane (H.8 partition)→S → S2106f6d

Per-surface partition isolation by default — AppSettings.browserPartitionMode = "per-surface" derives persist:browser-<id> per pane so cookies / localStorage / IndexedDB don't cross-contaminate. Two gmail-account panes can now coexist.

Remaining long tail (deferred from P7)

These items were explicitly captured for future P7 sessions. None are blocking the AAA distribution we landed; they push specific A-grade features to S or shrink the B/C cluster.

Cluster F — high-risk refactors

  • F.6 settings.schema.ts single source of truth. settings.ts is 1166 LOC / ~396 fields — needs a dedicated session.
  • A6 typed EventBus — 47+ ad-hoc window.dispatchEvent channels.
  • A7 VariantContext — drop the __tau* window globals.
  • F.11 WorkspaceCollection — extract from SurfaceManager.

Clusters G + H + C

  • H.9 session cap + manifest-auth + cross-site origin check.
  • Theme literal-to-token migration (~1013 hard-coded colour literals; audit:theming reports them).
  • Sidebar drag-reorder polish.
  • Notifications detail-expansion modal for long bodies (U8).

Plus the small S6 cleanup punt: plumb browserSearchEngine through SurfaceManager properly (currently passes the literal "google" default since the manager doesn't retain AppSettings).
